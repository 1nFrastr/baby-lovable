# Chat 回合一致性：目标与约束

本文只描述**产品目标与硬约束**，不绑定现有实现、历史方案或临时补丁。供重新设计读写模型与 UI 同步时使用。

---

## 一句话目标

用户在「发送 → 生成中 → 刷新/重进 → 停止/完成」任一时刻看到的对话，都应与**唯一权威状态**一致：不闪、不串、不丢、不重复；工具行显示真实终态，而不是把历史再演一遍。

---

## 用户可感知的正确行为

### 1. 生成中刷新 / 重进同一会话

- 已产生的用户消息、助手文字、已结束的工具调用，刷新后**立刻**以终态出现（例如 Wrote / Listed / Read），而不是先 Running 再「重放」成完成。
- 尚未结束的当前工具可以显示进行中；已结束的不得倒退回进行中。
- Composer：服务端仍在跑时保持锁定并可 Stop；结束后可立即再发。不得因刷新误判为已结束而叠开新一轮。

### 2. 同一会话不得叠跑

- 同一 session 同时最多一个活跃 builder 回合。
- 若用户在旧轮未结束时再次发送（竞态或误操作），必须先停掉旧轮再开新轮，不得多 workflow 并行抢同一工作区。

### 3. 消息列表稳定

- 同一逻辑消息只有一个稳定身份；刷新或流式更新不得复制出第二条「Listing / Writing / 同一段助手正文」。
- 回合内工具与文字的**时间顺序**保持模型真实顺序；不得因合并多路数据而乱序或把旧轮内容插进新轮。
- 新回合开始时，不得短暂闪出上一回合的助手气泡。

### 4. 正常结束与用户停止

- 正常跑完：最终落库内容与用户最后看到的一致（含总结性正文与已完成工具），刷新后仍在。
- 用户 Stop：保留当时已有的正文与已完成工具；进行中工具标记为中断；之后可立即再发。

### 5. 首轮与多轮一致

- 上述规则对「会话里第一轮」和「已有多轮历史」同样成立，不依赖「先聊几轮才正常」。

---

## 架构约束（设计时必须遵守）

### 单一权威读模型

- **进行中与已完成的对话历史，只认一条权威记录**（建议：session 上的消息列表）。
- 刷新后的首屏必须能仅凭这条权威记录还原「到目前为止」的完整回合进度（含已完成工具的终态）。
- 实时流（SSE 等）只负责**补当前正在变的尾部**（例如正在打出的字），不得充当刷新后的历史真相，也不得用「重放整段流」代替权威快照。

### 写入粒度

- 权威记录的更新粒度至少到：**每个 agent step 结束 / 每个工具调用完成**。
- 禁止「整轮结束才第一次写入助手进度」作为唯一落盘路径——那必然导致刷新只能靠不可靠旁路拼装。
- Token 级流式文字可以不落库；**离散事件（工具完成、step 边界）必须落库**。

### 工具状态单调

- 同一 `toolCallId`：`进行中 → 完成 / 中断`，禁止完成后再变回进行中。
- 权威快照里已是完成态的工具，任何合并/恢复路径都不得用更「新」但未完成的流式片段覆盖掉。

### 稳定消息身份

- 每一轮助手气泡在回合开始就有**稳定 id**，中途更新只替换同一条，不追加第二条助手消息。
- 流式通道若使用临时 id，合并进权威视图时必须归并到该稳定 id，禁止双 id 并存导致重复渲染。

### 回合生命周期单一裁决

- 「是否在跑 / 能否发送 / 显示 Stop」只认一套服务端回合状态（可与消息权威同源）。
- 前端本地流状态、Realtime、缓存等只能做加速提示，**不得在刷新后单独裁决为可发送**从而叠跑。

---

## 明确非目标

- 不要求刷新后无缝续上每一个 token 的打字机动画。
- 不要求为性能做过度优化；**正确性优先于减少写库次数**。
- 不要求保留多套并行真相源（正式消息 + 草稿 + 流重放 + 另一路 runtime）长期共存；旁路若存在，不得参与「用户看见什么」的裁决。

---

## 验收清单

- [ ] 生成中刷新 2–3 次：已完成工具始终为终态；无整段 Writing→Wrote 重放感。
- [ ] 刷新后无重复气泡、无旧轮闪入、无工具/正文乱序。
- [ ] 刷新后若仍在跑：Composer 锁定且可 Stop；结束后可马上发送。
- [ ] 同 session 不会出现多个并行 builder 回合；故意再 POST 会取消旧轮。
- [ ] Stop 后已产生内容仍在；再刷新仍在。
- [ ] 正常结束后总结正文仍在；再刷新仍在。
- [ ] 新会话第一轮即满足以上全部行为。

---

## 给实现者的设计提示（可选）

以下不是规定实现，只是与目标对齐的常见切法：

1. **读路径**：`显示 = 权威 messages`；仅当本页仍连着当前回合的活流时，用 live tail **覆盖最后一条助手的流式文本**（且不得降级已完成工具）。
2. **写路径**：回合开始写入稳定助手占位；每 step / 每 tool 完成 upsert 同一条；结束或取消再写终态并解锁回合。
3. **刷新**：不要依赖「把 SSE 从头重放一遍」来恢复 UI；权威快照应已足够。Live 只接续尚未持久化的尾部文本（若需要）。
4. **合并函数**：若必须合并两路快照，规则应是「完成态工具单调保留 + 稳定 id 归并」，而不是「谁 parts 多谁赢」。

---

## 成功标准

任意时刻问：「用户刷新后看到的，是否等于服务端权威消息里这一轮的最新快照（外加可选的当前流式尾巴）？」

答案必须稳定为**是**。若否，则模型仍未收敛。
